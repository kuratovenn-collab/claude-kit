# reviewers — итоги проверки

Как проверяли: реальные прогоны `claude -p --plugin-dir .` в **настоящих git-репозиториях** с заранее заложенными ошибками, а также на вставленном тексте (A/B-тест) и HTML-странице. Оценщик сверял каждое замечание с кодом, сам запускал тесты на копии репозитория и пересчитывал статистику и контраст. Обязательная проверка — `git status` после ревью: ревьюеры не должны ничего менять. Оценки 1–5: решает задачу / понятно новичку / без ложных замечаний / соответствие.

Исправления: описание начинается с фраз-триггеров, включая «всё ли честно в анализе» и «оцени дизайн». После этого (б) и (в) прогнаны повторно — скилл включился, вызваны `kit:stats-reviewer` и `kit:design-reviewer`:

- design: найдены градиенты, стекломорфизм, эмодзи, штампы; контраст посчитан верно — 5/4/4/4.

Другие исправления после раунда 1: раздел «Мутации» в отчёте обязателен; тесты не запускать без следов (`python -B -m pytest -p no:cacheprovider`, сравнение `git status`); готовые команды PowerShell; пояснение терминов во всех ролях; новый пример в SKILL.md, не совпадающий с тестовыми репозиториями.

## Раунд 2

| Сценарий | Итог | Оценка |
|---|---|---|
| (а) Новый репозиторий: инъекция команд через `os.system`, `open` без кодировки, `last_n(…, 0)`, регистр в поиске, жёсткий путь, тест `>= 0` | Найдены все заложенные ошибки и ещё одна настоящая; мутации в отчёте; файлы не изменены. Но **субагенты не запущены** («дифф маленький»), а пример атаки содержал разрушающую команду | 5/4/4/3 |
| (в) Почти «чистое» изменение (`slugify` с хорошими тестами) | Выдуманных замечаний нет; оценщик подтвердил запуском, что `pytest` без `conftest.py` действительно падает с `ModuleNotFoundError`, а `python -m pytest` проходит. Но приоритеты завышены («критично» для проблемы с рабочей альтернативой) | 4/4/4/5 |
| (б) Режим без субагентов (как в claude.ai) | Прогон не состоялся из-за ошибки в тестовом скрипте (опция запуска «съела» текст запроса) — перепроверено в контрольном раунде | — |

Исправления после раунда 2:
- субагенты запускаются **всегда**, когда доступны; сам — только если инструмента Agent/Task нет;
- калибровка приоритетов: «критично» — только если ломается основной сценарий без обходного пути; итог соразмерен найденному;
- номера строк — из файла, а не из заголовков диффа;
- примеры атак — только безвредные (`& echo test`), никогда не команды удаления;
- test-reviewer проверяет, запустятся ли тесты обычной командой;
- design-reviewer явно называет кнопки-пилюли, `→` и Inter; шапка отчёта обязательна.
