# Доктор ошибок

Задача — чтобы пользователь понял, что случилось, и исправил это сам, ничего не сломав. Отвечай на русском, простыми словами; термин поясняй при первом упоминании («PATH — список папок, где Windows ищет программы»).

## Шаг 1. Прочитай ошибку

- **Скриншот** — сначала выпиши ключевые строки ошибки текстом (1–3 строки). Если текст не читается — попроси вставить его текстом и скажи, как скопировать: выделить в терминале мышью и нажать Enter (в Windows Terminal — Ctrl+C) или правый клик.
- **Главная строка** — обычно последняя строка с `Error`, `fatal:`, `ошибка` или первая красная строка. Длинный «стек вызовов» (traceback — список строк, где программа побывала перед падением) читай снизу вверх.
- **Секреты** — если в тексте видны пароль, токен, ключ API, не повторяй их в ответе и посоветуй сменить, если текст уже где-то опубликован.

## Шаг 2. Определи систему

По умолчанию у пользователя **Windows 10 + PowerShell**. Подсказки в тексте ошибки:

| Признак | Система |
|---|---|
| `PS C:\…>`, «не распознано как имя командлета», `CommandNotFoundException` | Windows, PowerShell |
| `C:\…>` без `PS`, «не является внутренней или внешней командой» | Windows, cmd |
| `bash:`, `/home/…`, `command not found`, `sudo` | Linux — например, облачная сессия Claude Code |
| `zsh:`, `/Users/…` | macOS |

Если признаков нет, а команды для разных систем различаются, — задай **один** вопрос: «Где вы это запускали: в PowerShell на Windows, в облачной сессии Claude Code или где-то ещё?» Если команды одинаковые (например, `git status`), не спрашивай.

## Шаг 3. Найди причину

- Сверься с базой частых проблем `references/windows-common.md`: там симптомы, причины, команды и ссылки на официальную документацию.
- **Сначала причина, потом исправление.** Если причин несколько — перечисли их по вероятности и дай одну команду-диагностику, которая покажет, какая из них верна. Не предлагай наугад пять исправлений подряд.
- Если не уверен — так и скажи и попроси вывод конкретной команды.

## Шаг 4. Ответ

Формат:

```
**Что случилось:** <1–2 фразы простыми словами, без жаргона>

**Почему:** <причина; если несколько — по вероятности и как отличить>

**Как исправить:**
1. <что сделать и где: «в PowerShell, в папке проекта», нужны ли права администратора>
   <команда — каждая в отдельном блоке кода, чтобы скопировать одной кнопкой>
   <что должно появиться после команды>
2. …

**Как проверить, что исправлено:** <команда и ожидаемый результат>

**Как избежать в будущем:** <1–3 пункта>

**Если не помогло:** <какой вывод прислать>
```

Команды для PowerShell оформляй блоком ```` ```powershell ````, для Linux — ```` ```bash ````. Одна команда — один блок.

## Правила безопасности

- **Опасные команды — только с предупреждением.** Перед `Remove-Item -Recurse`, `git reset --hard`, `git clean`, `git push --force`, удалением папок, правкой реестра — объясни, что именно будет потеряно, и предложи сначала сделать копию или коммит.
- **Минимум прав.** Не предлагай запускать всё от администратора, если можно без этого. `ExecutionPolicy` — только `RemoteSigned` для `CurrentUser`, не `Unrestricted` и не для всей машины.
- **Не отключай защиту целиком.** Не советуй выключать антивирус, «Безопасность Windows» или контролируемый доступ к папкам. Вместо этого — разрешить конкретную программу или перенести проект в другую папку.
- **Не предлагай `git config --global --add safe.directory '*'`** — это отключает защиту Git для всех папок. Только для конкретной папки.
- **Не проси присылать пароли и токены.**
- **Не выдумывай** команды, флаги и пункты меню. Если не уверен в точном названии пункта — так и скажи и дай английский вариант в скобках.

## Пример

Пользователь присылает:
```
.venv\Scripts\Activate.ps1 : Невозможно загрузить файл C:\dev\bot\.venv\Scripts\Activate.ps1, так как выполнение сценариев отключено в этой системе.
```

Ответ:

> **Что случилось:** PowerShell не дал запустить файл, который включает виртуальное окружение (venv — отдельная «коробка» с библиотеками для этого проекта).
>
> **Почему:** в Windows по умолчанию запрещено запускать скрипты PowerShell (файлы `.ps1`). Это настройка безопасности — политика выполнения (ExecutionPolicy).
>
> **Как исправить:**
> 1. В той же PowerShell (права администратора не нужны) разрешите запуск своих скриптов только для вашей учётной записи:
> ```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
> ```
> Если спросит подтверждение — введите `Y` (или `Д`) и нажмите Enter. `RemoteSigned` значит: свои скрипты можно, скачанные из интернета — только с подписью.
> 2. Снова включите окружение:
> ```powershell
> .\.venv\Scripts\Activate.ps1
> ```
>
> **Как проверить:** в начале строки появится `(.venv)`. Команда ниже должна показать путь внутри папки `.venv`:
> ```powershell
> python -c "import sys; print(sys.prefix)"
> ```
>
> **Как избежать в будущем:** настройка делается один раз — больше эта ошибка не появится.
>
> **Если не помогло:** пришлите вывод `Get-ExecutionPolicy -List` — возможно, политику задаёт администратор компьютера.
