# Шаблоны результатов

Заполняй конкретикой из интервью. Разделы, которые не нужны, убирай. Угловые скобки `<…>` — места для подстановки, в готовом тексте их быть не должно.

---

## 1. Краткое ТЗ

```markdown
# <Название>

**Цель:** <зачем это нужно, какую проблему решает — 1–2 фразы>
**Для кого:** <кто пользуется и в какой ситуации>

## Что должно уметь
Обязательно:
1. <функция — описана как действие пользователя и результат>
Желательно (если останется время):
- <…>

## Ограничения
- <система, технологии, сроки, бюджет, навыки>

## Критерии готовности
- [ ] <проверяемое условие: «пользователь может … и видит …»>

## Вне рамок (не делаем сейчас)
- <…>

## Открытые вопросы и допущения
- Допущение: <…>
- Вопрос: <…>
```

---

## 2. Промт для чата (claude.ai)

Для разовой задачи в обычном чате: текст, анализ, объяснение, план.

```text
Контекст: <кто я, что уже есть, для чего результат — только то, что сказал пользователь; всё додуманное — с пометкой «Допущение:»>.

Задача: <что сделать — одной-двумя фразами>.

Требования:
- <обязательное>
- <желательное, если есть>

Как понять, что ответ хороший: <критерии: объём, уровень сложности, что обязательно должно быть>.

Проверки: отделяй факты от предположений; если в чём-то не уверен — так и напиши; не выдумывай источники и цифры. Не утверждай, что код работает или выводит именно это, если ты его не запускал: можешь запустить — запусти и покажи вывод, не можешь — пометь «не проверено запуском». <Если нужны ссылки: «проверь ключевые факты поиском и дай ссылки».>

Если что-то в задаче неясно — сначала задай мне 1–3 уточняющих вопроса, потом отвечай.

Формат ответа: <структура, длина, язык, таблица/список/текст>.
```

## 3. Промт для этапа в Claude Code

Для одной законченной задачи в репозитории, под присмотром пользователя.

```text
Контекст:
- Проект: <что это, язык, фреймворк, где главные файлы>.
- Я новичок. <ВАРИАНТ «КОМПЬЮТЕР»: Работаю на Windows 10 + PowerShell — команды для меня пиши под PowerShell.> <ВАРИАНТ «ОБЛАКО»: Ты работаешь в облачной сессии (Linux, bash) в уже открытом репозитории; новый репозиторий не создавай. Ветка: <имя>. Контейнер удаляется после сессии, поэтому в конце закоммить и запушь изменения в эту ветку. Команды, которые я буду запускать у себя, пиши под Windows PowerShell.>
- Уже сделано: <…>.

Цель этапа: <что должно появиться или измениться и зачем>.

Объём:
- Делать: <список>.
- Не трогать: <файлы, модули, поведение, которые менять нельзя>.

Требования:
1. <…>

Критерии готовности:
- [ ] <проверяемое условие: тест, команда, наблюдаемое поведение>
- [ ] Все существующие тесты проходят.

Обязательные проверки:
- Запусти <команды: тесты, линтер, сборка> и приведи их реальный вывод.
- Не заявляй, что тесты, сборка или проверка прошли, если ты их не запускал. Если запустить не удалось — так и напиши, с причиной.
- Перед изменением незнакомого кода прочитай его; не придумывай API, которых нет в проекте.

Если что-то неоднозначно: <«спроси меня, прежде чем продолжать» ИЛИ «выбери разумный вариант и запиши решение в отчёт»>.

Отчёт в конце:
1. Что сделано (по пунктам).
2. Какие файлы изменены.
3. Как проверено — команды и их вывод.
4. Что не сделано или сделано не полностью, и почему.
5. Следующий шаг.
```

## 4. Автономный промт «на ночь»

Для долгой работы Claude Code без подтверждений. Главное — чтобы работа не потерялась при обрыве, и чтобы агент не сделал ничего необратимого.

```text
Работаешь автономно, без моих подтверждений. Я вернусь через <N часов> и прочитаю отчёт.

Контекст:
- Проект: <…>. Ветка: <имя ветки> — работай только в ней.
- Я новичок, у меня Windows 10 + PowerShell — команды для меня в отчёте пиши под PowerShell.
- <ВАРИАНТ «ОБЛАКО»: Ты в облачной сессии (Linux, bash), репозиторий уже открыт — работай в нём, не создавай новый. Контейнер удалится, если работа не запушена: всё сохраняется только через push.>

Цель: <итог, который я хочу увидеть утром>.

Задачи по приоритету (самое важное — первым):
1. <…>
2. <…>
Если время кончается — лучше полностью сделать первые задачи, чем начать все.

Критерии готовности для каждой задачи:
- <проверяемые условия>

Обязательные проверки:
- После каждой задачи запускай <тесты/сборку> и сохраняй вывод для отчёта.
- Не заявляй, что что-то работает или тесты прошли, без реального запуска. Не удалось проверить — так и напиши.

Сохранность работы:
- После каждой завершённой задачи — коммит с понятным сообщением и push в <ветку>. <Если удалённого репозитория нет — только коммит.>
- Веди файл <DECISIONS.md / раздел «Статус» в CLAUDE.md>: что сделано, что в работе, что дальше.

Неоднозначность:
- Не жди меня. Выбери разумный вариант, запиши его и причину в <DECISIONS.md>, продолжай.
- Если задача заблокирована — запиши, что мешает, и переходи к следующей.

Запрещено:
- Удалять данные и файлы вне задачи, переписывать историю git (force-push, rebase опубликованных веток), пушить в main.
- Тратить деньги, регистрироваться в сервисах, публиковать что-либо наружу.
- Расширять задачу: не добавляй функций, о которых я не просил.

Отчёт в конце (в <REPORT.md> и последним сообщением):
1. Что сделано — по задачам, со ссылками на коммиты.
2. Как проверено — команды и вывод.
3. Принятые решения и почему.
4. Что не сделано и что мешало.
5. Что мне проверить самому и следующий шаг.
```

## Как использовать (проверено по документации Claude Code, ноябрь 2026)

Пиши пользователю только то, что относится к выбранному шаблону. Другие режимы и флаги не придумывай.

**Промт для чата.** Вставить первым сообщением в новый чат claude.ai. Приложить файлы, если промт на них ссылается.

**Промт для этапа Claude Code.**
- Облачная сессия: на claude.ai/code выбрать репозиторий и ветку (ветка — отдельная линия изменений, чтобы не трогать основную версию), вставить промт первым сообщением. Режим разрешений — выпадающий список под полем ввода. Если репозиторий совсем пустой — сначала создайте в нём файл README через сайт GitHub, чтобы был хотя бы один коммит.
- Компьютер: открыть PowerShell в папке проекта, запустить `claude`, вставить промт.
- После: прочитать отчёт; для разбора отчёта пригодится скилл report-explainer.

**Автономный промт «на ночь».**
- Надёжнее — **облачная сессия** (claude.ai/code): работа идёт в отдельном контейнере, компьютер можно выключить. В списке режимов под полем ввода выбрать **Auto**, если он есть (Claude сам выполняет действия, а фоновые проверки отсекают опасные); в режиме **Accept edits** правки файлов идут без вопросов, а команды могут ждать подтверждения. Режима без проверок в облаке нет. **Если Auto в списке нет** — не оставляйте сессию на ночь в Accept edits: она остановится на первой команде и будет ждать. Варианты: запускать днём и отвечать на вопросы; или заранее добавить в репозиторий файл `.claude/settings.json` с разрешёнными командами (правила `permissions.allow`, см. раздел Permissions в документации Claude Code). Утром смотреть ветку и отчёт: работа сохранена, только если она запушена (push — отправка коммитов на GitHub).
- **На компьютере**: `claude --permission-mode auto` — режим auto, при котором Claude выполняет команды без вопросов после фоновой проверки безопасности (по документации он снижает число вопросов, но не гарантирует безопасность). Режим `acceptEdits` для ночи не подходит: без вопросов идут только правки файлов и простые файловые команды, а git и тесты будут ждать ответа. Режим `bypassPermissions` (отключает все проверки) — только в изолированной среде (контейнер, виртуальная машина), не на рабочем компьютере.
